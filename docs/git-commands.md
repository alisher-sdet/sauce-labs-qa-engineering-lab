# Git Commands Cheat Sheet

Шпаргалка по Git и GitHub для проекта Sauce Labs QA Engineering Lab.

## 1. Проверка состояния репозитория

### Проверить состояние Git

```bash
git status
```

Показывает изменённые, новые и удалённые файлы, а также состояние staging area.

### Краткий статус

```bash
git status --short
```

Основные обозначения:

| Обозначение | Значение                                                    |
| ----------- | ----------------------------------------------------------- |
| `??`        | Новый файл, не отслеживаемый Git                            |
| ` M`        | Изменённый файл, изменение ещё не добавлено в staging       |
| `A `        | Новый файл добавлен в staging                               |
| `M `        | Изменение добавлено в staging                               |
| `D `        | Удаление файла подготовлено к коммиту                       |
| `MM`        | Файл изменён и после добавления в staging изменился ещё раз |

### Посмотреть текущую ветку

```bash
git branch
```

### Посмотреть последние коммиты

```bash
git log --oneline -5
```

Показывает пять последних коммитов в кратком формате.

## 2. Анализ изменений

### Посмотреть изменения в отслеживаемых файлах

```bash
git diff
```

Показывает изменения, которые ещё не добавлены в staging.

### Проверить ошибки пробелов

```bash
git diff --check
```

Проверяет незастейдженные изменения на распространённые ошибки пробелов.

### Посмотреть краткую статистику

```bash
git diff --stat
```

Показывает изменённые файлы и количество затронутых строк.

### Посмотреть подготовленные изменения

```bash
git diff --cached
```

Показывает содержимое изменений, добавленных в staging.

### Проверить подготовленные изменения

```bash
git diff --cached --check
```

Проверяет подготовленные изменения на распространённые ошибки пробелов.

### Посмотреть статистику подготовленных изменений

```bash
git diff --cached --stat
```

## 3. Подготовка файлов к коммиту

### Добавить конкретный файл

```bash
git add docs/git-commands.md
```

### Добавить каталог документации

```bash
git add docs/
```

### Добавить все изменения в текущем репозитории

```bash
git add -A
```

Используй эту команду внимательно: она подготовит все обнаруженные изменения, включая удаления файлов.

### Убрать файл из staging, сохранив его изменения на диске

```bash
git restore --staged docs/git-commands.md
```

### Проверить staging

```bash
git status --short
git diff --cached --check
git diff --cached --stat
git diff --cached
```

Перед коммитом убедись, что в staging находятся только нужные изменения.

---

## 4. Создание коммита

### Создать коммит

```bash
git commit -m "docs: add Git command cheat sheet"
```

Коммит сохраняет подготовленные изменения в локальной истории Git.

### Проверить последний коммит

```bash
git log -1 --oneline
```

### Посмотреть подробности последнего коммита

```bash
git show --stat HEAD
```

### Примеры сообщений коммитов

```bash
git commit -m "docs: add mobile testing commands"
git commit -m "test(mobile): add products screen tests"
git commit -m "test(web): add product sorting tests"
git commit -m "test(api): add product endpoint tests"
ci: update GitHub Actions workflow
```

Принятые префиксы в примерах:

- `docs` — документация;
- `test` — тесты;
- `ci` — CI/CD.

## 5. Работа с удалённым репозиторием GitHub

### Посмотреть удалённые репозитории

```bash
git remote -v
```

### Скачать информацию об удалённых изменениях

```bash
git fetch origin
```

Команда обновляет информацию об удалённых ветках, не объединяя изменения с текущей веткой.

### Проверить состояние ветки относительно удалённой

```bash
git status -sb
```

### Отправить коммиты в GitHub

```bash
git push origin main
```

Отправляет локальные коммиты текущей ветки `main` в удалённую ветку `origin/main`.

### Посмотреть связанные ветки

```bash
git branch -vv
```

**Важно:** перед `git push` проверь локальные изменения, коммиты и результаты необходимых тестов.

## 6. Отмена и временное сохранение изменений

### Отменить незастейдженные изменения файла

```bash
git restore path/to/file
```

Осторожно: команда удаляет незастейдженные изменения выбранного файла.

### Убрать изменения из staging

```bash
git restore --staged path/to/file
```

Содержимое файла на диске при этом сохраняется.

### Временно сохранить изменения

```bash
git stash
```

### Посмотреть сохранённые изменения

```bash
git stash list
```

### Вернуть последние сохранённые изменения

```bash
git stash pop
```

Перед восстановлением проверь состояние репозитория, чтобы избежать конфликтов.

### Отменить коммит отдельным обратным коммитом

```bash
git revert <commit-hash>
```

Команда создаёт новый коммит, отменяющий изменения указанного коммита.

Не используй `git reset --hard` без понимания последствий: эта команда может уничтожить незакоммиченные изменения.

## 7. Стандартный рабочий процесс

Рекомендуемая последовательность для проекта Sauce Labs QA Engineering Lab.

### Шаг 1. Проверить состояние

```bash
git status --short
```

### Шаг 2. Проверить изменения

```bash
git diff
git diff --check
```

### Шаг 3. Запустить необходимые проверки

Для изменений Web/API-кода:

```bash
cd web-api
npm run typecheck
npm run lint
npm run format:check
npm test
```

Для изменений мобильного кода:

```bash
cd mobile
uv run --locked ruff check .
uv run pytest -v
```

Для чисто документальных изменений полный набор тестов обычно не требуется.

### Шаг 4. Подготовить изменения

Из корня репозитория:

```bash
git add docs/
```

Добавляй только те файлы, которые должны попасть в коммит.

### Шаг 5. Проверить подготовленные изменения

```bash
git status --short
git diff --cached --check
git diff --cached --stat
git diff --cached
```

### Шаг 6. Создать коммит

```bash
git commit -m "docs: add Git command cheat sheet"
```

### Шаг 7. Отправить изменения

```bash
git push origin main
```

### Шаг 8. Проверить CI

Открой GitHub Actions и убедись, что необходимые workflow завершились успешно.

## 8. Краткая памятка

| Цель                        | Команда                   |
| --------------------------- | ------------------------- |
| Проверить состояние         | `git status --short`      |
| Посмотреть изменения        | `git diff`                |
| Проверить пробелы           | `git diff --check`        |
| Добавить файлы              | `git add <path>`          |
| Проверить staging           | `git diff --cached`       |
| Создать коммит              | `git commit -m "message"` |
| Посмотреть историю          | `git log --oneline -5`    |
| Скачать информацию с GitHub | `git fetch origin`        |
| Отправить коммиты           | `git push origin main`    |
| Проверить последний коммит  | `git show --stat HEAD`    |

## 9. Правила безопасности

- Не коммить секреты, токены, пароли и реальные `.env`-файлы.
- Не добавляй все файлы без предварительной проверки `git status`.
- Не отправляй изменения до необходимых локальных проверок.
- Не используй разрушительные команды без понимания их последствий.
- После отправки изменений проверяй GitHub Actions.
- Предпочитай небольшие коммиты с одной понятной целью.
